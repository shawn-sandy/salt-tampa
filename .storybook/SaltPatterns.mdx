# Salt Tampa design tokens

Every value the Salt patterns use resolves to one of the tokens below. They are
transcribed from the design canvas `Salt Tampa Homepage.html` and live in
`src/styles/salt/_salt-tokens.css`; the classes that consume them live beside
it in `_salt-patterns.css`.

This set is deliberately **separate** from the older `--st-*` tokens in the same
folder. The two describe different generations of the same brand at materially
different scales — 14px body against 16px, a 34px section heading against 48px,
a 10px photo radius against 20px. Merging them would silently reflow the shipped
home page, which renders on `--st-*`. No variable name is shared, so both sets
coexist.

## Deviations from the design file

Everything is transcribed verbatim except the entries below. Each carries the
same note in the token file itself. Every ratio quoted here was **measured**
with axe-core against the rendered page, not estimated.

### Legibility floor

| Token            | Design | Here   | Why                                                                                               |
| ---------------- | ------ | ------ | ------------------------------------------------------------------------------------------------- |
| `--salt-text-xs` | 10.5px | `12px` | Carries the footer's legal row. A sub-12px floor would become permanent on every page built here. |
| `--salt-text-sm` | 12.5px | `14px` | Carries service-card body copy — running prose, not a label.                                      |

### Measured contrast

The design's terracotta carries white 13px button labels and 16px band copy at
**3.23:1** where WCAG 1.4.3 asks for 4.5:1, and its badge text sits at
**4.33:1** on its own tint. Each colour below is darkened by the _smallest_
amount that clears the threshold, so the palette stays recognisably itself.

| Token                 | Design    | Here      | Measured after     |
| --------------------- | --------- | --------- | ------------------ |
| `--salt-orange`       | `#d97347` | `#b25e3a` | 4.61:1 with white  |
| `--salt-orange-hover` | `#c25f36` | `#9f4e2c` | 5.83:1 with white  |
| `--salt-orange-deep`  | `#b8542c` | `#b3522b` | 4.53:1 on the tint |
| `--salt-sage`         | `#5e8f7e` | `#547f70` | 4.52:1 with white  |
| `--salt-sage-hover`   | `#4d7a6a` | `#456d5e` | 5.83:1 with white  |
| `--salt-scrim-flat`   | 0.42      | `0.58`    | 5.48:1 donate body |

Two scrims are **additions**, because axe cannot judge text over a photograph
and the real measurements were far worse than the drawing suggests. Sampling
the lightest pixel under each text run, the hero's white copy measured
**1.39:1** and the header's links **1.09:1**. `--salt-scrim-header` puts a
backdrop under the navigation bar and `--salt-scrim-hero-text` darkens only the
band the hero's text sits in, leaving the top of the photograph alone. The same
measurement afterwards reads 8.3:1 and 8.6:1.

`--salt-muted` (`#a1a1aa`, 2.56:1 on white) is transcribed verbatim because no
pattern uses it. Do not put text in it without darkening it first.

## Two things to know before you extend this

**Links need a doubled class.** `@fpkit/acss` declares
`a[href] { background-color; border-radius; color; font-size; font-weight }` at
specificity (0,1,1). A single `.salt-x` class is (0,1,0) and loses all five —
measured, not assumed: a probe declaring an orange background at 13px measured
as `rgba(0, 0, 0, 0)` at 16px. Any class that can land on an `<a href>` is
written `.salt-x.salt-x` to reach (0,2,0).

**Motion is opt-out by the operating system.** The design specifies none, but an
instant slide swap reads as a glitch. `.salt-slide` cross-fades inside a
`@media (prefers-reduced-motion: no-preference)` block using `@starting-style`,
so under `reduce` no transition is declared at all.
